RELIEFSYNC DESK / ARCHITECTURE

A small system. A deliberate human checkpoint.

One FastAPI process serves the desk, API, queue workers and Telegram long polling. SQLite holds durable intake, suggestions and the audit trail.

From message to decision

Intake: Telegram updates and the protected intake endpoint persist messages before processing. Duplicate Telegram delivery is idempotent; unfinished queued intake is restored on restart.

Understanding: A configurable Chat Completions service extracts validated fields. Timeouts and provider errors fall back to visibly labelled rules. Gazetteer lookup works without network access; remote geocoding is opt-in and cached.

Coordination: Same-sender repeats are grouped. Different senders stay separate. Compatible items within the configured radius become suggestions, with score breakdowns.

Human approval: A transaction prevents two coordinators from allocating the same card. Approval reserves the pair and rejects conflicting suggestions. Notifications have a visible delivery state and an explicit retry on failure.

Private by design

Public lists receive redacted text and coordinates placed within an approximate grid cell. Exact coordinates and raw source text are available only in authenticated coordinator details. Simulation never posts into Telegram.

Where it runs

Vultr Ubuntu Compute → Caddy HTTPS → non-root Python container → persistent SQLite volume. Use a single Uvicorn worker. Higher traffic requires a shared queue, transactional server database and distributed limits before adding workers.
