# Connect Telegram

No live bot is pre-created. The owner needs a Telegram account; only BotFather can issue its bot token.

1. In Telegram, open the verified **@BotFather** account. Send `/newbot`, choose the display name and a unique username ending in `bot`.
2. Store the returned token in the ignored `.env` as `TELEGRAM_BOT_TOKEN`. Set `TELEGRAM_BOT_USERNAME` without `@`. Never share a screenshot containing the token; use BotFather to revoke it if exposed.
3. Send `/setprivacy` to BotFather, select this bot, and choose **Disable**. Remove/re-add the bot to an existing test group if Telegram requires it for the setting to take effect. Alternatively, an admin bot can see group messages, but admin permissions are unnecessary for the basic prototype when privacy is disabled. See [Telegram FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).
4. Create a private, clearly named **ReliefSync simulated storm drill** group. Add the bot. Tell participants that messages are stored and publicly redacted/approximated on the desk. Use only fictional situations.
5. Copy its invite link into `TEST_GROUP_URL` if you intend to invite testers. Set an optional feedback URL. Restart/recreate the application to load the environment.
6. Keep `TELEGRAM_MODE=polling` initially. No public HTTPS endpoint is required for polling; the server needs outbound access. Run one process only with this bot token.
7. For local live Telegram testing, create a stable `SALT` and strong `COORDINATOR_TOKEN`. Do not rely on the ephemeral development salt across restarts. For deployment use the secrets generated by the setup script.

## Live acceptance test

- `/start`: check the emergency-service disclaimer and location instructions. `/status` warns when the bot’s `getMe` metadata does not indicate disabled privacy; admin bots may still work despite that conservative warning.
- From user A: `Need insulin in Velachery`.
- From a **different user B**: `I have insulin available in Velachery`.
- Check that both cards are **not** labelled Simulated, and a suggested match appears. Before approval no match notification should have been sent.
- Log in as coordinator. Expand the preview and approve. Verify the real group receives the approximate notification and requester/volunteer mentions. Completion changes both cards to fulfilled.
- Test a need without location, then send a location pin within 15 minutes in the same chat. The latest unresolved card should become locatable.
- Edit a message and confirm its existing card changes, and previous matches are invalidated.
- `/iam India` adds optional self-reported country information. `/status` counts your own active cards.
- `/privacy` explains storage; `/forget` erases your app records and rejects associated matches.
- Post an unsupported sticker/photo and confirm the text-and-pin notice is rate-limited. Voice/calls are not processed.

Native Telegram intake is real even while the dashboard is in demo mode, so only authenticated coordinators can approve those pairs. The built-in drill is always simulated and never sends Telegram notifications.

## Optional webhooks

Set `TELEGRAM_MODE=webhook`, a strong `TELEGRAM_WEBHOOK_SECRET` (≥24 characters), and the final HTTPS `PUBLIC_BASE_URL`. On startup the service registers the webhook and the secret-token header. Both the URL secret and `X-Telegram-Bot-Api-Secret-Token` must match. Polling startup removes an old webhook without dropping pending updates. Bot API reference: [setWebhook / getUpdates](https://core.telegram.org/bots/api).

## Common problems

| Problem | Resolution |
| --- | --- |
| Only slash commands arrive | Disable privacy in BotFather; remove/re-add the bot; check admin status |
| Nothing arrives | Check token, outbound connectivity, group membership and `/health` Telegram state |
| 409 conflict | Stop other pollers and select polling OR webhook, not both |
| Group notification fails | Ensure the bot can send messages and still belongs to the originating group |
| No match | Different users, same compatible resource, known nearby locations, open/unflagged cards |
| Duplicate notification after retry | Telegram does not provide exactly-once send semantics; inspect history before retrying uncertain delivery |
| `/forget` after salt change misses records | Restore the original salt and repeat deletion; do not rotate salts casually |

The transport is covered by mocked tests. A successful real-group test must be recorded separately after the owner configures the account.
